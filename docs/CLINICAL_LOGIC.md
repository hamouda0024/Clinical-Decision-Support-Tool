# المنطق السريري — Clinical Logic

> **تنبيه:** هذه الوثيقة تشرح محركاً تعليمياً مبسّطاً. النتائج احتمالية نسبية وليست
> تشخيصاً. لا تستخدم هذه الأداة أساساً وحيداً لأي قرار علاجي.

## 1. قاعدة المعرفة

`server/data/diseases/` تحتوي 24 حالة شائعة موزّعة على الصدمات القلبية والتنفسية
والهضمية والبولية والعصبية والغدية والنفسية. كل حالة تُعرَّف في `server/engine/types.ts`:

```ts
interface Disease {
  id: string;
  nameAr: string;
  nameEn: string;
  icd10?: string[];
  specialties: SpecialtyId[];
  summaryAr: string;
  symptoms: { id: string; weight: 1 | 2 | 3 }[];
  keyFindings: string[];          // العلامات المميزة (hallmarks)
  vitals: VitalCriterion[];       // علامات حيوية داعمة
  against?: DiscouragingCriterion[]; // أدلة سلبية
  riskFactors: RiskFactor[];
  redFlags: string[];
  actions: RecommendedActions;
  review?: { status: 'unreviewed' | 'in_review' | 'approved'; reviewer?: string; lastReviewedAt?: string };
  references?: ClinicalReference[];
}
```

- **الحوكمة:** غياب `review` يعني `unreviewed`. لا يمكن لحالة أن تُعلن `approved`
  دون اسم المراجع وتاريخ صالح ومصدر واحد على الأقل؛ وإلا يفشل التحقق عند بدء التشغيل.
  الحالة الإجمالية للقاعدة تُشتق من المدخلات وتُعاد في `meta.governance` و`/api/health`.

- **أوزان الأعراض:** 3 = علامة مميزة، 2 = داعمة، 1 = مساندة.
- **أدلة سلبية (`against`):** معيار حيوي عند تحققه يقلّل احتمال الحالة (مثل نقص
  الأكسجة في فقر الدم). يظهر في الواجهة تحت «عوامل لا تدعم هذا التشخيص».
- **سلامة البيانات:** `server/data/knowledge-base.ts` يتحقق عند بدء التشغيل من عدم
  وجود معرّفات أمراض مكرّرة أو أعراض/تخصصات غير معروفة، ويفشل التشغيل عند وجود خطأ.

## 2. حساب درجة الاحتمالية

لكل حالة تُحتسب ثلاث قنوات ثم تُدمج:

```
symptomScore = مجموع أوزان الأعراض المطابقة / مجموع كل أوزان أعراض الحالة
vitalScore   = مجموع أوزان المعايير الحيوية المتحققة / مجموع أوزان معايير الحالة
riskScore    = مجموع أوزان عوامل الخطورة المطابقة / مجموع أوزان عوامل الحالة

weights = { symptom: 0.60, vital: 0.28, risk: 0.12 }
```

- إذا لم تكن للحالة عوامل خطورة، يُعاد توزيع وزنها (0.12) على قناة الأعراض.
- **معامل العلامات المميزة:** `keyFactor = 0.75 + 0.25 × (عدد العلامات المميزة
  المطابقة / كل العلامات المميزة)`. يمنع الحالات ذات القوائم القصيرة من الهيمنة.
- **مكافأة التخصص:** +0.05 إذا كان تخصص الإدخال ضمن تخصصات الحالة.
- **توافق المدة الزمنية:** تُحوَّل مدة الأعراض إلى مسار (`hyperacute` ≤ 24 ساعة،
  `acute` ≤ 72 ساعة، `subacute` ≤ 14 يوماً، `chronic` بعدها) وتُقارن بالمسار
  المتوقع لكل حالة في `server/data/course.ts`: +0.03 عند التطابق، −0.03 عند
  الاختلاف بمسارين أو أكثر، ويظهر ذلك ضمن الأدلة أو العوامل غير الداعمة.
- **الخصم السلبي:** يُطرح `weight / 100` لكل دليل سلبي متحقق.
- تُقصّ النتيجة بين 1 و92، وتُرتّب تنازلياً، وتُعرض أفضل 6 حالات بحد أدنى 8.
  إذا لم تتجاوز أي حالة الحد، تُعرض أفضل 3 نتائج.
- درجة 92 هي سقف مقصود: الأداة لا تدّعي يقيناً تشخيصياً.

> الأرقام **نسبية داخل الأداة** ولا تمثل احتمالات سريرية مُعايَرة (calibrated).
> أي تعديل على الأوزان يجب أن يخضع لمراجعة سريرية واختبارات انحدار في
> `server/engine/assessment.test.ts`.

## 3. الفرز (Triage) ودرجة الإنذار المبكر

`server/engine/vitals.ts` يحوّل العلامات الحيوية إلى حالة (طبيعي/منخفض/مرتفع/حرج)
وإلى درجة إنذار مبكر مبسّطة من 0 إلى **11** (الحد الأقصى الحقيقي للقواعد الحالية،
ويُعاد في `earlyWarningMax`). الدرجة مستوحاة من بنية NEWS2 لكنها **ليست NEWS2**
ولا تستخدم معدل التنفس أو الوعي أو الأكسجين التكميلي، ولذلك تُعرض دائماً بعنوان
«EWS مبسّط» مع تنبيه صريح.

`server/engine/triage.ts` يرفع مستوى الفرز بشكل محافظ:

| المستوى | أمثلة على المحفّزات |
| --- | --- |
| طارئ | EWS ≥ 7، SpO₂ < 90%، ضغط انقباضي < 90، نبض > 130 أو < 40، حرارة ≥ 40 أو < 35، ألم صدري مع تعرّق/ضيق نفس، ألم تمزقي، أعراض سكتة، تيبّس رقبة مع حرارة، تورّم لساني، نزف هضمي. |
| عاجل | EWS 5–6، SpO₂ 90–93%، ضغط 90–99، حرارة ≥ 38.5، نفث دم، تخليط مع حرارة/عمر ≥ 65. |
| شبه عاجل | EWS 2–4 أو أعراض تستدعي المراقبة. |
| روتيني | لا محفّزات. |

## 4. التفسير والشفافية

كل نتيجة تتضمن:

- `matchedEvidence`: الأعراض والعلامات الحيوية وعوامل الخطورة الداعمة.
- `missingKeyFindings`: العلامات المميزة غير المُسجّلة (توضيح لما ينقص).
- `discouragingFindings`: الأدلة السلبية المتحققة.
- `redFlags`: إشارات الخطر الخاصة بالحالة.
- `actions`: الفحوصات المخبرية، التصوير، الإجراءات الفورية، الأدوية، والتحذيرات/الموانع.

## 5. الحدود المعروفة

- لا تُدخل الأدوية الحالية، الحساسية، الأمراض المزمنة، أو نتائج الفحوصات؛ لذلك لا
  يمكن كشف التفاعلات الدوائية الفعلية.
- لا تُدعم حالات الأطفال (دون 16 سنة) والحوامل بمعايير خاصة؛ يُضاف تنبيه صريح
  إلى `meta.limitations` عند إدخال عمر أقل من 16.
- قاعدة المعرفة ليست شاملة (24 حالة فقط) ولا تُحدَّث تلقائياً من المصادر.
- لا يوجد تعلّم آلي؛ السلوك حتمي وقابل للاختبار.

## 6. حوكمة المحتوى

تُدار حالة المراجعة في `server/data/governance.ts` و`Disease.review` / `references`.
القاعدة الحالية **غير مُراجعة** (`unreviewed`) ويعرض التطبيق هذا التنبيه قبل النتائج
وبعدها عبر `meta.governance` و`meta.limitations`.

أي إضافة أو تعديل على قاعدة المعرفة يتطلب:

1. مراجعة سريرية موثّقة من المشرف الطبي، ثم ضبط `review` و`references`.
2. الإشارة إلى مصدر/دليل سريري معتمد في وصف التغيير.
3. اجتياز `npm run typecheck` و`npm test` (يشمل اختبار سلامة معرّفات قاعدة المعرفة).
4. تحديث الاختبارات عند تغيير ترتيب التشخيصات المتوقعة.
5. إضافة الحالة إلى `server/data/course.ts` (وإلا يفشل التحقق عند بدء التشغيل).
