# Clinical Decision Support Tool

أداة ويب متكاملة (Full-stack) لدعم القرار السريري، موجّهة للأطباء والممارسين
الصحيين. تُدخل الأعراض الرئيسية والعلامات الحيوية للمريض، فتُعيد قائمة مرتّبة
بالتشخيصات التفاضلية مع درجة احتمال نسبية، والفحوصات المطلوبة، والإجراءات
الفورية، والأدوية المقترحة والتحذيرات والموانع، إضافة إلى مستوى فرز الحالة
وطبقة إنذار مبكر مبسّطة.

واجهة عربية بالكامل (RTL) بتصميم طبي هادئ، ومنطق تحليل منفصل على الخادم، وقاعدة
معرفة سريرية تعليمية مكتوبة بأنواع TypeScript صارمة.

> ## ⚠️ إخلاء مسؤولية طبي
> هذه الأداة **تعليمية لدعم القرار فقط**، ولا تُعدّ تشخيصاً نهائياً ولا بديلاً عن
> التقييم السريري المباشر والفحص البدني واستشارة الطبيب المختص. النتائج احتمالية
> ومبنية على قاعدة معرفة مبسّطة، ويجب التحقق منها دائماً وفق المعايير السريرية
> المعتمدة وحالة كل مريض على حدة. **لا تُستخدم لتخزين بيانات المرضى.**

## الميزات

- **نموذج تقييم شامل:** العمر، الجنس، التخصص الطبي، مدة الأعراض، اختيار متعدد
  للأعراض (قابل للبحث مع تمييز الأعراض الإنذارية)، وضغط الدم الانقباضي/الانبساطي،
  النبض، الحرارة، وتشبّع الأكسجين.
- **تشخيصات تفاضلية مرتّبة** حسب درجة احتمال نسبية، مع شرح لكل نتيجة: الأدلة
  الداعمة، العلامات المميزة الناقصة، والأدلة التي لا تدعم التشخيص.
- **إجراءات موصى بها لكل تشخيص:** فحوصات مخبرية، تصوير، تدخلات فورية، أدوية
  مقترحة، وتحذيرات وموانع استخدام.
- **فرز ثلاثي المستوى** (طارئ/عاجل/شبه عاجل/روتيني) مبني على العلامات الحيوية
  والأعلام الحمراء، مع أسباب القرار ودرجة إنذار مبكر مبسّطة.
- **تحقق مزدوج** (واجهة + خادم) برسائل خطأ عربية دقيقة.
- **لا يخزّن بيانات المرضى:** الحساب في الذاكرة، وواجهة API بلا كوكيز ومع
  `Cache-Control: no-store`.
- **أمثلة سريعة** لتجربة الأداة فوراً دون إدخال يدوي.
- **تصميم متجاوب** ولوحة نتائج لاصقة على الشاشات الكبيرة، مع دعم RTL كامل.

## التشغيل السريع

المتطلبات: **Node.js ≥ 20.19** و**npm**.

```bash
npm install          # يثبّت الحزم من package-lock.json
npm run dev          # يشغّل الخادم والواجهة معاً
```

- الواجهة: <http://localhost:3000>
- واجهة API: <http://localhost:4000/api/health>

يستخدم Vite وكيلاً (`/api` → `http://127.0.0.1:4000`)، لذلك تبقى الطلبات
same-origin في التطوير. لتشغيل الخادم فقط:

```bash
cp .env.example .env   # اختياري: اضبط PORT وALLOWED_ORIGINS
npm run dev:server
```

## الأوامر

| الأمر | الوصف |
| --- | --- |
| `npm run dev` | تشغيل API والواجهة (hot reload) |

| `npm start` | تشغيل نسخة الإنتاج (يقدّم الواجهة والـ API معاً) |

## واجهة API

### `GET /api/health`

```json
{ "status": "ok", "engineVersion": "1.0.0", "knowledgeBaseEntries": 24 }
```

### `GET /api/catalog`

يعيد الأعراض (مع مجموعاتها)، التخصصات، تعريفات العلامات الحيوية ووحدات المدة
والحدود المسموحة، لتُبنى الواجهة ديناميكياً من مصدر واحد.

### `POST /api/assess`

مثال طلب:

```json
{
  "age": 58,
  "sex": "male",
  "specialty": "emergency",
  "duration": { "value": 2, "unit": "hours" },
  "symptoms": ["chest_pain", "diaphoresis", "dyspnea"],
  "vitals": {
    "systolicBP": 150,
    "diastolicBP": 95,
    "heartRate": 108,
    "temperature": 37.1,
    "spo2": 93
  }
}
```

مقتطف من الاستجابة:

```json
{
  "triage": {
    "level": "emergency",
    "labelAr": "حالة طارئة — تدخل فوري",
    "earlyWarningScore": 3,
    "reasons": ["ألم صدري مع تعرّق/ضيق نفس — اشتباه متلازمة تاجية حادة"]
  },
  "vitals": [{ "id": "spo2", "value": 93, "status": "low" }],
  "differentials": [
    {
      "id": "acute_coronary_syndrome",
      "confidence": 60,
      "matchedEvidence": ["ألم في الصدر", "تعرق بارد", "ضيق في التنفس", "تسرّع القلب", "مدة الأعراض متوافقة مع المسار السريري"],
      "missingKeyFindings": [],
      "discouragingFindings": [],
      "actions": { "labs": ["…"], "imaging": ["…"], "immediate": ["…"], "medications": ["…"], "alerts": ["…"] }
    }
  ],
  "meta": { "engineVersion": "1.0.0", "lowInformation": false }
}
```

الأخطاء تعود بالشكل `{ "error": { "code", "messageAr", "issues?" } }` مع رموز
`400` (تحقق)، `403` (أصل غير مسموح)، `413` (حجم كبير)، `429` (تقييد المعدل)،
و`500` (خطأ داخلي دون كشف التفاصيل).

## محرك القرار السريري

يدمج المحرك ثلاث قنوات مرجّحة — تطابق الأعراض، والعلامات الحيوية، وعوامل
الخطورة — ثم يطبّق معامل تغطية العلامات المميزة، وتوافق مدة الأعراض مع المسار
السريري المتوقع للحالة، وخصماً للأدلة السلبية، ويعيد نتائج قابلة للتفسير.
تُصنَّف الحالات في أربعة مستويات فرز وفق EWS مبسّطة وأعلام حمراء.

التفاصيل الكاملة (الأوزان، عتبات الفرز، حدود الأداة، وحوكمة قاعدة المعرفة) في
[docs/CLINICAL_LOGIC.md](docs/CLINICAL_LOGIC.md).

## الأمان والخصوصية

- تحقق صارم على الخادم (Zod) يرفض الحقول الزائدة والقيم الشاذة ومعرّفات الأعراض
  غير المعروفة، ويحدّ حجم الطلب.
- رؤوس أمان عبر Helmet مع CSP (`default-src 'self'`) ومنع التضمين في إطار.
- تقييد المعدل على `/api`، ورفض طلبات الكتابة من أصول مختلفة.
- لا تخزين لبيانات المرضى أو تسجيلها، وردود بلا تخزين مؤقت.
- إخفاء آثار المكدّس في الأخطاء، وإخفاء `X-Powered-By`.
- لا أسرار في المستودع: `.env` مستثنى، والنموذج `.env.example` فقط.

التفاصيل وسياسة الإبلاغ عن الثغرات في [SECURITY.md](SECURITY.md).

## النشر

```bash
npm ci
npm run build
NODE_ENV=production PORT=4000 npm start
```

يقدّم الخادم ملفات `dist/client` مع SPA fallback، ويُبقي `/api` منفصلاً. عند
النشر خلف وكيل عكسي موثوق فعّل `TRUST_PROXY=true` واضبط `ALLOWED_ORIGINS` على
النطاقات الفعلية، واستخدم HTTPS. الأداة لا تتضمن مصادقة، لذا يجب حمايتها على
مستوى الشبكة قبل أي استخدام مؤسسي.

### GitHub Pages (نسخة تجريبية ثابتة)

ينشر سير العمل [`.github/workflows/pages.yml`](.github/workflows/pages.yml) الموقع
تلقائياً عند كل دفع إلى `main`:

1. من صفحة المستودع: **Settings → Pages → Build and deployment → Source** واختر
   **GitHub Actions**.
2. ادفع إلى `main` أو شغّل السير عمل يدوياً؛ يُنشر الموقع على
   `https://hamouda0024.github.io/Clinical-Decision-Support-Tool/`.

نسخة Pages لا تحتوي خادماً: تُضمَّن قاعدة المعرفة ومحرك القرار نفسه داخل الحزمة
وتُشغَّل في المتصفح، فلا تُرسل أي بيانات ولا تحتاج مسارات `/api`. للبناء محلياً:

```bash
npm run build:pages   # الناتج في dist/pages، بمسار أساس /Clinical-Decision-Support-Tool/
```

المسار الأساسي مضبوط في `vite.config.ts` عبر `PAGES_BASE`؛ يجب تحديثه إذا أُعيد
تسمية المستودع. أما النسخة الكاملة (API + الواجهة) فتُنشر بـ `npm run build && npm start`.
